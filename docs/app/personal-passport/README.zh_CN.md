# Player Pass 个人像素名片

Player Pass 是基于 FoloToy AI Passport 的派生应用：一台可随身携带的电子名片，展示像素头像、个人简介、游戏收藏、联系方式二维码，以及可配置的 NFC 入口内容。所有个人数据都保存在设备本地；没有云端账号、登录或 OTA 更新。管理后台提供手动 JSON 导出/导入，不提供自动备份。

固件面向文档定义的 ESP32-C3 主板（8 MB Flash、无 PSRAM、240 × 320 ST7789P3、三键 ADC 分压）。板级访问保留在 `components/bsp`，所有页面、任务、状态机和 Web 资源放在 `main`。

## 设备体验

### 按键

| 输入 | 动作 |
| --- | --- |
| UP / DOWN 短按 | 移动选中项，到两端后停住 |
| OK 短按 | 进入页面、显示二维码或打开详情 |
| OK 长按 | 返回上一级 / 关闭浮层 |
| 首页 OK 双击 | 进入管理模式 |

选中行始终有薄荷色边框与高亮文字。每个页面底部都有可用操作提示。

### 页面

1. **首页**：92 × 92 头像框、姓名、一句话介绍、三个平台行（Steam / Switch / PSN，含 ID 与二维码可用标记），以及三个导航行（游戏、联系方式、NFC）。在平台行按 OK 显示已上传的二维码；在导航行按 OK 进入对应页面。
2. **游戏**：一个连续列表，分为“喜欢的游戏”和“正在玩的游戏”。每行显示一张竖版封面、名称和简短信息。列表只渲染包含选中项在内的五个条目窗口，因此即使资料很多，LVGL 对象数量仍然很小。OK 进入游戏详情。
3. **游戏详情**：72 × 96 封面、名称、分组标签、小黑盒链接状态和简介。配置链接后，OK 会在设备上生成二维码供手机扫描。
4. **联系方式**：微博、微信昵称、微信号、微信二维码、微信收款码。文字项打开大字号只读面板；二维码项打开 180 × 180 的白底二维码页面。不会把全部二维码同时堆在页面上。
5. **NFC**：显示配置的标题、类型与内容。卡片上的 NTAG213 是无源标签，没有 MCU 接口；固件可以显示内容并生成二维码副本，但不能写卡。请用支持 NFC 的手机写入标签。
6. **管理模式**：固定页面显示 WPA2 热点名称、固定密码、可扫描的管理地址二维码、客户端与编辑租约状态、存储条，并支持长按 OK 手动退出。管理模式期间暂停普通页面导航。

每个页面右上角显示电量百分比；读不到电量时显示 `--`。

## 架构

```text
main/
  main.c                 BSP 启动，然后进入 app_core_start()
  app/                   生命周期、数据加载、输入任务、模式切换
  data/                  个人资料、游戏、NFC 模型与 JSON 校验
  storage/               可移植 POSIX 文件层、LittleFS 挂载、空间阈值
  image/                 PPIM 头、图片加载、设备端二维码生成
  session/               纯逻辑的编辑租约与空闲状态机
  wifi_manager/          WPA2 SoftAP 生命周期
  http_server/           管理 API 与内嵌 Web 资源
  ui/                    重新设计的设备页面、主题、图标
  font/                  字体声明与字形覆盖检查
  web_src/               管理后台源码
  web/web_assets.c       生成的 gzip 资源数组
  third_party/           cJSON 1.7.18 与 Nayuki QR 生成器（MIT）
```

LVGL 只在输入任务持有 `bsp_lvgl_lock()` 时访问。按键回调只负责入队。图片读取与 HTTP 服务在各自任务中运行。产品不播放声音，因此不初始化音频，以降低内部 RAM 占用与功耗。

## 存储与分区

设备使用一个 factory 应用分区（无 OTA）和一个 LittleFS 数据分区。NVS 只保存 Wi-Fi 校准数据；热点密码是固件内的固定密码。

| 分区 | 类型 | 偏移 | 大小 | 用途 |
| --- | --- | ---: | ---: | --- |
| `nvs` | data/nvs | `0x9000` | `0x6000` | Wi-Fi 校准 |
| `phy_init` | data/phy | `0xF000` | `0x1000` | PHY 数据 |
| `factory` | app/factory | `0x10000` | `0x300000` | 单一应用镜像 |
| `storage` | data/littlefs | `0x310000` | `0x4F0000` | JSON 记录与图片 |

交付构建的压缩应用镜像实测为 **2,120,592 字节**（`0x205B90`）。它占用 3 MiB factory 分区后仍剩余 1,025,136 字节（33%），为字体重新生成留出空间。数据分区为 `0x4F0000` 字节（约 4.94 MiB）。空白 LittleFS 分区在首次启动时格式化；非空但挂载失败的分区会报告为损坏，绝不自动格式化。

## 构建与验证

激活 ESP-IDF 5.5.3 后运行：

```bash
./tools/validate.sh --static
./tools/validate.sh --firmware
./tools/validate.sh
```

固件门禁会在隔离目录中构建、校验分区表与合并镜像，并输出 `build/FoloToy-AI-Passport-full.bin`。Host 门禁会运行可移植测试，以及 `tools/check_fonts.py`、`tools/pack_web.py --check` 和 `tools/gen_icons.py --check`。

## 刷写与数据影响

空白设备或需要完整刷新时，从 `0x0` 刷写合并镜像：

```bash
python -m esptool --chip esp32c3 -p <port> -b 460800 \
  write-flash 0x0 build/FoloToy-AI-Passport-full.bin
```

合并镜像会填充镜像之间的空隙，并重置 NVS（Wi-Fi 校准）。在本次实测构建中，合并镜像在 storage 分区之前结束，但未来构建或完整刷新不能依赖这一点；更大的镜像或不同布局可能触及数据区。产品提供管理后台的手动 JSON 导出；若需要保留数据，请在完整刷新前导出备份。分段开发刷写时，请使用兼容的分区布局，不要擦除 storage 分区。

没有 OTA、没有双应用分区、没有自动回滚。

## 字体

设备字体由 Fusion Pixel 12 px proportional（SIL OFL 1.1，2026.10.25 发布）生成，字号 12 px 与 24 px，1 bpp，行高 16 / 28。实测 Flash 占用为 721,318 字节（12 px 字体 187,267 + 24 px 字体 505,351 + 覆盖表 28,700）。字符清单共 7,393 个码点：可打印 ASCII、GB2312 符号区与源字体实际包含的一级/二级汉字，以及 `main/` 中出现过的全部非 ASCII 字符。源 TTF 不提交。来源 URL、哈希、转换工具版本与重新生成命令见 [`assets/README.zh_CN.md`](../../../assets/README.zh_CN.md#设备字体子集player-pass)。

清单之外的动态文字会被管理 API 拒绝；设备端遇到缺字会显示 `?` 并记录 `U+XXXX` 日志。需要扩大支持范围时，重新生成两套字体并重新编译固件。固件不宣称支持任意 Unicode。

## 管理后台

管理后台以可复现的 gzip 数组编译进固件，通过 `http://192.168.4.1` 访问，支持手机与桌面浏览器的横竖屏。热点使用 WPA2 固定密码保护（密码定义在固件中并显示在设备屏幕上）；后台本身没有登录密码。第一个取得租约的浏览器拥有编辑权，其他浏览器可以查看状态并知道设备已被占用。文字修改与图片上传都通过临时文件和原子替换写入 LittleFS。

管理后台的“备份”页会把个人资料、游戏、NFC 和全部图片导出为一个 JSON 文件；导入需要编辑租约，并会覆盖当前数据。存储格式、备份格式与全部 API 见 [data-and-api.zh_CN.md](data-and-api.zh_CN.md)。

自动化：

- `./tools/validate.sh --static` 通过。
- `./tools/validate.sh --firmware` 产出并校验合并镜像。
- Host 测试覆盖 UTF-8、JSON、原子替换、图片校验、空间阈值、游戏分组、租约/宽限/空闲状态机与字体覆盖。

真机（构建成功不能替代）：

- 启动进入重新设计的首页；头像、姓名、介绍、平台 ID、电量正常显示。
- 三个按键：选择到端点停住、OK 动作、长按返回、首页双击进入管理模式。
- 游戏分组与窗口滚动、详情页、设备端二维码生成。
- 联系方式文字面板与已上传二维码/收款码。
- NFC 页面与二维码内容。
- 管理热点可见、WPA2 生效、屏幕显示 SSID/密码/地址；反复进出不泄漏任务或 socket。
- 手机打开后台；个人资料、游戏、图片、联系方式、NFC 修改在重启后仍保留。
- 第二个浏览器显示“被占用”；第一个浏览器心跳保持租约；宽限期、不自动退出与长按 OK 手动退出符合文档。

- 管理模式显示管理地址二维码；手动导出生成 JSON 文件，导入能恢复文字与图片；失败时报告失败步骤（不自动回滚）。
- 每个页面的中文显示，包括动态姓名与被拒绝的缺字。

## 管理页面没有响应

如果手机已经连上 `PlayerPass-XXXX`，但 `http://192.168.4.1` 超时：

1. 看设备的管理模式屏幕：应显示“热点与管理页面已开启”并出现管理地址二维码。
   如果显示“正在开启热点…”或“启动失败：管理页面：…”，说明 HTTP 服务没有启动；
   长按 OK 退出后重新进入管理模式，并查看错误或 USB 日志。
2. 在手机 Wi-Fi 详情里确认地址在 192.168.4.0/24 网段、网关为 192.168.4.1。
   如果拿不到地址或地址以 169.254 开头，忘记网络后重连，或重启设备。
3. 精确打开 `http://192.168.4.1/`：不要用 HTTPS、不要加 `.local`、不要加端口。
   换隐私窗口或另一个浏览器；关闭 VPN 与 Private Relay；Android 关闭该热点的
   “自动切换到移动数据”，在“无互联网”提示时选择继续保持连接。
4. 用同一热点下的电脑执行：

   ```bash
   ping -c 4 192.168.4.1
   ```

   ```bash
   curl -v --max-time 5 http://192.168.4.1/api/status
   ```

   ping 不通是连接/DHCP 问题；ping 通但 curl 超时是 HTTP 服务问题，重新进入
   管理模式并查看设备状态/日志。
5. 热点最多允许 3 个客户端，断开不用的设备。
6. 如果设备还是旧固件，请刷当前完整镜像；新的管理模式屏幕会显示地址二维码和
   更明确的启动失败原因。
7. 如果热点一直正常但 HTTP 始终不启动，用数据线连接 USB Serial/JTAG，确认出现
   `/dev/cu.usbmodem*` 后抓取日志。

热点按设计没有互联网，但本地页面仍应可以打开；不要依赖强制门户自动弹出。

## 限制与未验证项

- NTAG213 内容不能由固件写入；它是给外部 NFC 写卡工具使用的配置。
- 热点没有互联网时手机行为因系统而异。iOS 通常保留移动数据；部分 Android 会把流量路由到热点并暂时失去互联网。未在所有机型上验证。
- Web 后台不会请求小黑盒或任何外部服务。游戏链接以二维码形式给手机；跨域与反爬行为不属于固件范围。
- 热点密码是固件内的固定密码，知道密码的人都能加入；后台没有登录。需要更换密码时重新编译固件。
- 备份仅限手动 JSON 导出/导入；不提供自动备份、ZIP、历史版本、恢复点或回滚。刷写或文件系统故障可能导致数据丢失。
- 设备实际渲染、按键手感、Wi-Fi 距离、电量读数与 USB 行为都需要真机验收。
